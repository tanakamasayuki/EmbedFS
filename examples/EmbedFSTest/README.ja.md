# EmbedFSTest

> English: [README.md](README.md)

読み取り専用FSの操作と書き込み拒否を確認するサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [EmbedFSTest.ino](EmbedFSTest.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<EmbedFS.h>`

同じフォルダの必要ファイル: [assets_embed.h](assets_embed.h)

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `fs.open(...)` — 対象の入力／ファイルを開けたことと、種類が目的に合うことを確認します。
2. `root.openNextFile(...)` — 列挙されたEntryを確認し、使用後にcloseします。Directoryと通常ファイルを区別します。
3. `file.close(...)` — 資源の利用を終え、それに属するviewやハンドルを使わないようにします。
4. `EmbedFS.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。

## APIの使い方と注意点

EmbedFSは読み取り専用です。リポジトリの手順で埋め込み用の表を生成し、生成物をスケッチと一緒にビルドします。PC上の元ファイルを変えても書き込み済みの内容は変わりません。

`begin()` でツリーを公開し、`open()` や列挙で得たFS形式のオブジェクトは有効性とディレクトリ種別を確認します。データがある間だけ読み、最後にcloseします。試験例のWrite・Rename・Mkdir・Removeは、書き込み可能なフラッシュ操作ではなく、読み取り専用として拒否されることを確認します。

元データと生成物を対応させ、生成コマンドはバージョンを転記せずルートREADMEを参照します。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

```text
Listing directory: %s
 - not a directory
  DIR :
```

## 確認と問題の切り分け

読み取り専用FSの操作と書き込み拒否を確認することを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
